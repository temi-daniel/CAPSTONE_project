CAPSTONE PROJECT BRIEF

This repository provisions two connected AWS environments with Terraform:

1. **Project 1 (frontend)** — a static React website served via ECS Fargate + ALB, backed by a private RDS PostgreSQL instance (provisioned to demonstrate secure database networking, even though the static site itself doesn't use it).
2. **Project 2 (backend)** — a Node.js/Express app running on EKS, which does use the RDS instance to serve a live

Both environments live in the same VPC, in `us-east-1`, so the EKS node security group can reach the RDS security group directly.

## Architecture

```
                              Internet
                                 │
                 ┌───────────────┴───────────────┐
                 │                                │
           Public Subnets                   Public Subnets
                 │                                │
        ┌────────▼────────┐              ┌────────▼────────┐
        │  ALB (Project 1) │              │  NLB (Project 2) │
        └────────┬────────┘              └────────┬────────┘
                 │                                │
           Private Subnets                  Private Subnets
                 │                                │
        ┌────────▼────────┐              ┌────────▼────────┐
        │  ECS Fargate      │              │  EKS Node Group  │
        │  (website task)   │              │  (2x t3.small)   │
        └────────┬────────┘              └────────┬────────┘
                 │                                │
                 └───────────────┬────────────────┘
                                 │
                        ┌────────▼────────┐
                        │  RDS PostgreSQL  │
                        │  (private subnet)│
                        └──────────────────┘

        Secrets Manager: RDS master credentials (Terraform-generated)
        ECR: 2 repositories (website image, project-app image)
```

**Key design points**

- All compute (ECS tasks, EKS nodes) and the database run in **private subnets** with no public IP. The only public-facing components are the ALB (Project 1) and the LoadBalancer Service (Project 2), both provisioned in public subnets.
- **Security groups** enforce the access chain: ALB → ECS (port 80 only), EKS nodes → RDS (port 5432 only). Nothing else can reach the database.
- **RDS credentials** are generated by Terraform and stored in AWS Secrets Manager — never written to a `.tf` file, Dockerfile, or committed anywhere.
- **Terraform state** is stored remotely in an encrypted S3 bucket, never committed to Git.

## Deploying from scratch

### 1. Create the Terraform state backend (one-time, if it doesn't already exist)


Update the `backend "s3" {}` block in both `frontend/terraform/provider.tf` and `backend/terraform/provider.tf` with your bucket name.

### 2. Deploy the frontend infrastructure (VPC, ECS, ALB, RDS)

```bash
cd frontend/terraform
terraform init
terraform apply
```

This creates the shared VPC, both ECR repositories, the ECS cluster/service/task definition, the ALB, RDS, and the Secrets Manager secret.

### 3. Build and push the website image using CI pipeline

ECS will pick up the new image on the next service deployment (or force one: `aws ecs update-service --cluster <cluster> --service <service> --force-new-deployment`).

### 4. Deploy the backend infrastructure (EKS)


This creates the EKS cluster, managed node group (2x t3.small), and the security group rule allowing EKS nodes to reach RDS on port 5432. **Node group creation takes 10–20 minutes** — this is normal.

### 5. Connect kubectl to the new cluster

```bash
aws eks update-kubeconfig --name execute-eks --region us-east-1
kubectl get nodes
```

Confirm both nodes show `STATUS = Ready` before continuing.

### 6. Build and push the Project 2 app image

```bash
cd ../app
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <account-id>.dkr.ecr.us-east-1.amazonaws.com
docker build -t execute-project-app .
docker tag execute-project-app:latest <account-id>.dkr.ecr.us-east-1.amazonaws.com/execute-project-repo:latest
docker push <account-id>.dkr.ecr.us-east-1.amazonaws.com/execute-project-repo:latest
```

### 7. Create the Kubernetes Secret from the values Terraform generated

```bash
SECRET_JSON=$(aws secretsmanager get-secret-value --secret-id execute/rds/master-credentials --region us-east-1 --query SecretString --output text)

kubectl create secret generic db-credentials \
  --from-literal=DB_HOST=$(echo $SECRET_JSON | jq -r .host) \
  --from-literal=DB_USER=$(echo $SECRET_JSON | jq -r .username) \
  --from-literal=DB_PASSWORD=$(echo $SECRET_JSON | jq -r .password) \
  --from-literal=DB_NAME=$(echo $SECRET_JSON | jq -r .dbname)
```

Never write these values into a committed YAML file. See `backend/kubernetes/secret-template.yaml` for the expected shape only.

### 8. Deploy the Kubernetes manifests

```bash
cd ../kubernetes
kubectl apply -f deployment.yml
kubectl apply -f service.yml
kubectl get pods -w
```

Wait until both pods show `READY 1/1`.

### 9. Get the app's public URL

```bash
kubectl get svc project-app
```

Open the `EXTERNAL-IP` DNS name in a browser — you should see the visit counter incrementing on each refresh.

## Destroying everything

Destroy in **reverse order** of creation, since the backend depends on the frontend's VPC/subnets:

```bash
# 1. Remove Kubernetes resources first (releases the LoadBalancer)
cd backend/kubernetes
kubectl delete -f service.yml
kubectl delete -f deployment.yml
kubectl delete secret db-credentials

# 2. Destroy the EKS cluster
cd ../terraform
terraform destroy

# 3. Destroy the frontend infrastructure (VPC, ECS, ALB, RDS, ECR)
cd ../../frontend/terraform
terraform destroy
```
